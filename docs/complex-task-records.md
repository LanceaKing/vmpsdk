# 复杂任务过程记录

凡是通过复杂过程完成的任务，必须在 `docs/` 中新增或更新对应的 Markdown 文档，记录完整、可复现的过程，并将文档作为任务交付的一部分。复杂过程包括多轮搜寻、逆向分析、多步骤环境搭建、反复排错或多方案试验等。

过程记录必须另开分支聊天（子代理）执行。主聊天向分支聊天提供任务目标、实际操作记录、原始证据和验证结果；分支聊天负责整理文档、核对证据链及链接存档，主聊天在交付前检查文档与实际工作一致。

- 记录任务目标、环境与前提条件，以及实际使用的工具和版本。
- 记录资料、下载地址和关键数据的来源及获取方法；涉及解码、解包或格式转换时，说明算法、参数和文件映射。
- 按实际操作顺序记录步骤，提供可复现的命令或脚本、关键输入与输出。
- 记录失败尝试、关键错误、排查依据、修正方法及最终方案的选择原因。

文档中的链接按以下规则存档：

- 本仓库的 GitHub 链接不存档，包括仓库文件、代码提交、CI 运行和产物链接；指向本仓库文件的相对链接也不存档。
- 其余链接默认通过 [Wayback Machine Save Page Now](https://web.archive.org/save) 逐一提交存档，包括来源页面、下载地址和其他仓库的 GitHub 链接。文内锚点随所在文档处理。
- 文件大于 2 GB（2,000,000,000 字节）且已经完整下载到本地时，改用 [Internet Archive Upload](https://archive.org/upload) 上传本地文件。下载片段、缓存块和解包后的部分文件不算完整下载。
- 在文档中保留原始链接，并记录对应的快照或上传条目 URL、存档日期和结果。实际打开快照核对内容；上传文件还须核对文件名、大小和校验摘要。
- 无法公开访问或存档失败的链接，记录原地址、失败原因及未完成状态。提交请求或打开存档入口不算存档成功，只有取得并验证快照或上传文件后才能标记完成。

后续修改影响上述过程时，由分支聊天同步更新对应文档，并对新增或变更的链接执行相同的存档流程，使记录与当前实现一致。
